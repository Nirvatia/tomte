# Roadmap

План составлен по результатам ревью кода. Переписывать всё с нуля не нужно: архитектура нормальная, слои разделены, тесты зелёные. Основные проблемы сидят в слое хранения, там же корень большинства багов. Остальное решается точечной чисткой.

Порядок этапов выбран так: сначала то, что теряет данные и подвешивает вкладку, потом чистка кода, потом задачи из старого TODO, потом UX, потом новые фичи.

Обозначения: `[ ]` не сделано, `[x]` сделано.

---

## Этап 1. Хранение и потеря данных

Самое важное. Раньше весь проект (промпты, вложения в base64, файлы дерева) хранился одной записью в IndexedDB и перезаписывался целиком при каждом автосохранении.

**Итог этапа.** База переведена на схему v2 с миграцией. Автосохранение пишет около 1 КБ вместо всего проекта (на проекте с вложением 20 МБ было примерно 20 МБ на каждое сохранение). Миграция проверена в Chromium на старой базе. Тесты базы переведены на `fake-indexeddb`.

- [x] **1.1. Отложенное сохранение теряет правки.** `createFlushableAsync` (`src/utils/index.ts`): если `flush()` или таймер срабатывает во время идущего сохранения, функция дожидается его и выходит. Флаг `dirty` остаётся поднятым, но повторный запуск никто не планирует, и последние правки висят в памяти до следующего нажатия клавиши. Закрыл вкладку — потерял. Исправить и покрыть тестами.
- [x] **1.2. Разнести хранение по object store'ам.** Схема БД v2:
  - `projects`: метаданные и файлы промптов (лёгкая запись);
  - `attachments`: вложения, по записи на файл, с индексом по `projectId`;
  - `trees`: дерево проекта вместе с содержимым файлов, одна запись на проект.

  Автосохранение редактора пишет только `projects`. Вложения и дерево пишутся, только когда меняются сами.
- [x] **1.3. Миграция v1 → v2.** Существующие проекты при открытии раскладываются по новым хранилищам. Без потерь.
- [x] **1.4. GitHub-токен в каждом узле дерева.** Сейчас токен копируется в `githubRef` каждого узла, на большом репозитории это тысячи копий в базе. Хранить токен только в `githubConfig` проекта, а узлы оставить с `owner/repo/branch`. Заодно вычистить токен из узлов при миграции.
- [x] **1.5. Клик по файлу промпта не всегда переключает.** Каждое переключение ждёт `flush` тяжёлого сохранения. При двух быстрых кликах побеждает тот, чей `await` завершился последним, а не последний клик. Нужно, чтобы выигрывал последний клик, а сохранение стало быстрым (1.2). *Сделано: гонка исправлена и покрыта тестом. Что баг из старого TODO был именно этим, вживую не подтверждено: если повторится, нужен сценарий воспроизведения.*
- [ ] **1.6. Зависание неактивной вкладки.** Предполагалось, что уйдёт после 1.2. Замер в headless Chromium на проекте с вложением 20 МБ этого не подтвердил: и старая, и новая версия сохраняют без long tasks. Причина не найдена. Нужен сценарий воспроизведения: какие файлы были загружены, сколько вкладка простояла, браузер. Потом профиль в DevTools (Performance и Memory) после возврата на вкладку.
- [x] **1.7. Менеджер проектов грузит всё.** `loadAllProjects()` поднимает из базы все проекты со всеми вложениями, только чтобы нарисовать список. Сделать лёгкий `loadProjectSummaries()`.
- [x] **1.8. Один лимит размера.** Сейчас их два: 25 МБ на содержимое дерева (`projectActions.ts`) и 50 МБ на проект (`types`). Оставить один лимит на проект, а бюджет дерева считать от него.
- [x] **1.9. Размер проекта не обновляется при наборе текста.** Автосохранение не пересчитывает `totalSize`. Пересчитывать дёшево, по разнице длины файла, без `new Blob()`.
- [x] **1.10. Тесты на реальной IndexedDB.** Перевести тесты базы с ручных моков `idb` на `fake-indexeddb`, проверить миграцию, раздельное сохранение и порядок вложений.

## Этап 2. Чистка кода

- [ ] **2.1. Один `updateProject(mutator)`.** Блок «скопировать проект → пересчитать размер → положить в стор → сохранить» повторяется в `projectActions.ts` около 15 раз. Свести в одну функцию, файл похудеет примерно вдвое.
- [ ] **2.2. Убрать дублирование стора дерева.** Дерево лежит и в `activeProject.projectTreeSource`, и в `projectTreeNodes`/`projectTreeRootName`/`projectTreeString`. Оставить один источник, остальное сделать `derived`.
- [ ] **2.3. Разобрать «Legacy stores».** Проверить, что из `stores/index.ts` ещё используется (`fileName`, `exportFormat`, `editorHtml`...), лишнее удалить.
- [ ] **2.4. `svelte-check` без ошибок.** Сейчас 13 ошибок: типы для `turndown-plugin-gfm` и `"strike"` в `export/md.ts`, плюс типизация моков в `TreeNodeItem.test.ts`. Добавить `npm run check` в обязательные проверки.
- [ ] **2.5. Код не должен подстраиваться под моки.** `processFile` (`utils/files.ts`) держит `FileReader`/`Image` «чтобы тестовые моки работали». Переписать на `createImageBitmap` или `file.arrayBuffer()`, тесты поправить под код, а не наоборот.
- [ ] **2.6. Бинарные файлы, которые не картинки.** PDF, zip и прочее сейчас уходят в ветку `Image` и падают. Сделать для них отдельный тип вложения (только метаданные).
- [ ] **2.7. Предупреждения компилятора.** `TreeNodeItem.svelte:31` (`state_referenced_locally`), `autofocus` в `PromptsSection.svelte`.
- [ ] **2.8. Тесты: меньше разметки, больше сценариев.** Тесты на разметку модалок (`ProjectManagerModal.test.ts`, около 900 строк; `TagManagerModal.test.ts`, около 700) ужать. Добавить сценарные тесты: переключение файла во время сохранения, вставка во время загрузки, смена проекта с несохранённым текстом. Это ответ на вопрос из старого TODO «нужно ли 500 тестов»: число не проблема, проблема в том, что они проверяют не то.
- [ ] **2.9. Линтер и форматтер.** ESLint + Prettier, единый стиль, проверка в CI.
- [ ] **2.10. Починить e2e.** 3 из 10 Playwright-тестов падают, причём и до изменений этапа 1: `editor.spec.ts` (создание файла через табы), `project-tree.spec.ts` (секция Prompts, закрытие по Escape). Тесты отстали от UI.
- [ ] **2.11. CI.** GitHub Actions: `check`, `test`, `build` на каждый PR.

## Этап 3. Задачи из старого TODO

- [ ] **3.1. Вставка дерева затирает текст.** Причина: `.setCodeBlock()` в `ProjectTreeSection.svelte` превращает текущий абзац в блок кода. Вставлять отдельный узел `codeBlock` после курсора.
- [ ] **3.2. Кнопка удаления на блоке дерева.** Свой NodeView для блока с деревом, с кнопкой «убрать из промпта».
- [ ] **3.3. Менеджер промптов.** Выбор нескольких файлов, удаление пачкой, экспорт нескольких файлов сразу (ZIP).
- [ ] **3.4. Контраст текста.** `--text-dim: #4d6b69` на фоне `#141819` даёт около 3:1, а нужно не меньше 4.5:1 (WCAG AA). Поднять примерно до `#6f8f8c` и пройтись по местам вроде «Загрузите файлы или перетащите их сюда».
- [ ] **3.5. Активная кнопка тулбара.** Белая иконка на ярко-бирюзовом не читается. На заливке `--accent` иконка должна быть тёмной, или сделать заливку приглушённой.
- [ ] **3.6. DOCX по ГОСТу.** Возможно: библиотека `docx` умеет поля, шрифт, интервалы, отступ первой строки, нумерацию. Сделать пресет «ГОСТ 7.32» (поля 30/15/20/20, Times New Roman 14, интервал 1.5, отступ 1.25 см) как опцию экспорта.

## Этап 4. Мелкие баги

- [ ] **4.1. Вставка картинки откуда угодно.** `onpaste` висит на `window`, поэтому картинка, вставленная в модалку или инпут, становится вложением. Ловить вставку только в редакторе.
- [ ] **4.2. При запуске открывается не тот проект.** Берётся проект с самым свежим `updatedAt`, а должен открываться последний открытый. Хранить id последнего открытого.
- [ ] **4.3. Токен дублируется при копировании проекта.** Спрашивать, копировать ли токен, или не копировать вовсе.

## Этап 5. UX

- [ ] **5.1. Честный статус сохранения.** Вместо вечно мигающего «Автосохранение включено» показывать «Не сохранено / Сохранение / Сохранено». При ошибке выводить toast с кнопкой «Повторить».
- [ ] **5.2. Отмена удаления.** Вместо `confirm` на каждый чих показывать undo-toast на 5 секунд (`svelte-sonner` уже подключён).
- [ ] **5.3. Горячие клавиши.** `Ctrl+S` сохранить, `Ctrl+P` найти файл, `Ctrl+W` закрыть вкладку, `Ctrl+Shift+E` экспорт. Плюс шпаргалка по `?`.
- [ ] **5.4. Действия без мыши.** Кнопки «переименовать/удалить» видны только при наведении (`opacity-0`). Показывать их по `focus-within`, добавить контекстное меню по правому клику.
- [ ] **5.5. Перетаскивание.** Менять порядок вкладок и файлов промптов мышью.
- [ ] **5.6. Поиск по дереву.** Фильтр по имени и пути. Без него на большом репозитории делать нечего.
- [ ] **5.7. Разбивка токенов.** В StatusBar показывать, сколько уходит на промпт, вложения и дерево. Выбор целевой модели с её лимитом контекста.
- [ ] **5.8. Первый запуск.** Сейчас встречает пустой проект. Нужен короткий онбординг или демо-проект.
- [ ] **5.9. Метки вложений в тексте.** Подсвечивать `[IMAGE_1]` и `[FILE_1]` в редакторе, по клику открывать превью вложения. Предупреждать, если метка ссылается на удалённое вложение.
